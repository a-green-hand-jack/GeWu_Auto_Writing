# Paper construction architecture

PaperWriter is a long running research workflow, not a text expansion script.
The coordinator owns the scientific narrative and keeps a source bound ledger.
It composes intake and evidence mapping, domain and venue assessment, planning,
section drafting, independent review, supported revision, compilation and visual
receipt through the backend's native capabilities.

Use skills for durable procedures and knowledge files for rules and domain
criteria. Use bounded tools for deterministic inventories, hashes, provenance,
compilation and consistency checks. Use sub-agents only for independent
literature, figure or review work; the coordinator remains the single owner of
framing and section prose. Hooks or backend events may persist stage transitions
and enforce handoff requirements, but must never certify scientific truth.

When a solution repository is small, expand explanation rather than claims:
define the problem, assumptions, notation, derivation or proof, evidence
protocol, scope, relation to prior work, limitations and implications. A short
source is a reason to write a careful expository paper, not an outline.
